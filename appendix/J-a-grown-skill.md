# 附錄 J　打開一份長大的技能檔

## J-0　為什麼要看一份完整的

第 3 章教你建技能檔，用的例子是一個五段的小檔案。附錄 F 講了十二個設計模式，但那是在描述**形狀**。

兩者中間有一段空白：你知道要從摩擦開始，也知道有哪些模式，卻沒看過一份真的長大之後的東西長什麼樣。這一頁補那一段。

下面是我實際在用的引用查核技能。它從一段「幫我看這個引用能不能用」的提示詞開始，用了幾個月變成現在這樣。

**這份已經縮過。** 本機路徑改成了通用寫法，變更紀錄只留一則。結構與判準表是完整的，長度大約是原檔的一半。

⚠️ **看的時候請帶著 J-4 那個提醒**：你的第一版不該長這樣，而且不可能長這樣。

## J-1　先看骨架

十八節。這是它現在的目錄：

```
觸發情境總表
模式選擇（開場第一件事）

模式 A：quick
  判斷請求類型
  引用輸出結構

模式 B：grilled（三角色審查流程）
  Agent 1：Finder（工作者）
  Agent 2：Challenger-Advisor（質疑者＋指導者）
    ⓪ 存在查核 — 七大判準之前
    七大判準（每筆逐項回答，不可跳過）
    判準 4b、7 的自動化查核
  Agent 3：Gatekeeper（全域守門員）
  最終輸出

共用規範（兩種模式皆適用）
  改寫六大原則
  引用出處格式規則
  多引用點全篇分析
與其他技能的分工
邊緣情況處理
參考資料
變更紀錄
```

先注意兩件事。

第一，**「模式 A／模式 B」不是兩個技能，是同一件事的兩種深度。** 這解決一個很實際的問題：你不會為了確認一筆書目格式就啟動三個角色的對抗審查，但你也不希望投稿前的全稿掃描被草草帶過。

第二，**〈邊緣情況處理〉這一節在最開始不存在。** 它是每次撞到牆之後多加一列長出來的。

## J-2　逐段看

### 觸發：它自己決定什麼時候該出現

```
⚠️ 強制觸發：任何在草稿中新增 in-text citation 或 References 條目的動作，
不論來源，都必須經本技能。

| 類別 | 觸發短語 |
|------|---------|
| 顯式引用 | 「要引用這篇」「這個觀點可以引用嗎」 |
| 嚴格審查 | 「這個引用站得住腳嗎」「幫我掃全篇引用」 |
| 搜尋推薦整合 | 「把這些文獻引用進草稿」「推薦的文獻整合進去」 |
| 尚無文獻 | 「幫我找能支持這個論點的文獻」 |
| 隱式觸發 | 當即將插入 (Author, Year) 引用時，即使使用者未說「引用」，
             仍須暫停走本技能 |
```

**這一段在防什麼**：最後一列。前面四列是我開口叫它，最後一列是**它自己該想起來**。

那一條是我又一次差點出錯之後才補的——我沒說「引用」，只說「幫我把這段補完整」，於是它順手加了一筆我沒查過的來源。第 3 章講「技能是長出來的」，這一行就是長出來的地方。

### 模式路由：開場第一件事

```
| 模式 | 何時用 | 流程 |
|------|--------|------|
| quick（預設） | 單篇、引用點明確、只要寫法 | 直接走引用輸出結構 |
| grilled | 要進正式投稿、論點吃重、來源多篇、對某引用不確定 | 走三角色流程 |

自動升級規則：以下任一成立，主動提議切到 grilled——
- 一次丟 3 篇以上
- 論點涉及因果宣稱（「導致」「造成」「提升了」）
- 來源樣本脈絡與研究脈絡明顯不同
- 說「這篇能不能支持⋯⋯」而非「幫我引用⋯⋯」
- 文獻來自搜尋推薦且無全文 —— 此情境強制 grilled
- 將引用寫入正式投稿草稿 —— 自動升級

降級規則：說「快速版」「先看看」→ 一律 quick。
```

**這一段在防什麼**：預設值選錯。

⚠️ **注意「自動升級」與「降級」是不對稱的**。升級的條件寫了六條而且有兩條是強制，降級只要我說一句話。這個不對稱是刻意的：**要它更嚴格應該很容易發生，要它放鬆應該需要我明確開口。**

倒數第三條是我踩過的：文獻來自搜尋推薦、而且沒有全文的時候，最容易發生「看起來很合適所以就用了」。

### 七大判準：這一頁最該抄走的東西

```
| # | 判準 | 要問的問題 |
|---|------|-----------|
| 1 | 主張匹配度 | 原文真的說了你要它說的話嗎？ |
| 2 | 過度延伸 | 用法是否超出原研究的樣本、脈絡、效果量？ |
| 3 | 證據層級 | 實證？綜述？二手引用？ |
| 4 | 時效與被取代 | 是否已有更新或推翻此結論的來源？ |
| 4b | 影響力佐證 | 被引數與同年同域相比如何？被引的極性是什麼？ |
| 5 | 脈絡對齊 | 樣本族群／年齡層／文化脈絡可遷移嗎？ |
| 5b | 年齡層遷移性 | 來源年齡差距＞3 年時，機制是否跨齡可遷移？ |
| 6 | 必要性 | 在撐論點還是裝飾？ |
| 7 | 來源正當性 | 有 DOI？已撤稿／勘誤／關切聲明？ |
```

**這一段在防什麼**：憑印象放行。

「每筆都要逐項回答，不可跳過」那一句是關鍵。⚠️ **沒有那一句，這張表會退化成一個心裡的印象**——你掃過去覺得「大致沒問題」，然後放行。有那一句，你得對第 3 列寫下「二手引用」這四個字，而寫下來的那一刻你就知道它撐不住方法論宣稱。

判準 4b 值得多說一句。它原本只寫「被引幾次」，後來改成「被引的極性」：一篇被引 200 次、其中多數是被拿來**反駁**的，那它不是領域共識，是靶子。**單看總被引數完全看不出這件事。**

### 三個角色：為什麼要拆開

```
Agent 1：Finder（工作者）
  把論點轉成可檢索的主張，找出候選段落。
  輸出：每筆以結構化紀錄呈現（含逐字引文 ＋ 精確位置 ＋ 驗證層級）

Agent 2：Challenger-Advisor（質疑者＋指導者）
  逐筆審查引用正當性，通過者當場產出引用寫法。
  預設立場是懷疑。

Agent 3：Gatekeeper（全域守門員）
  審全篇分布，≥5 筆引用時執行。
  | 項目 | 紅線 |
  | 作者集中度 | 單一作者群 >30% |
  | 一句多引用 | 一句 4+ 引用無區辨 |
  | 自我引用 | >20% |
  | 年份分布 | 五年內 <40% 或 >90% |
  | 全文驗證覆蓋率 | >50% 仍為「未經全文驗證」→ 警告 |
  | 撤稿／關切聲明 | 出現任一即紅線，不是比例問題 |
```

**這一段在防什麼**：找的人跟審的人是同一個。

三個角色分開，是因為 Finder 剛把那段話挑出來，它記得的是「我為什麼覺得這段合適」。**讓它回頭審自己，它看到的是自己的理由，不是紙上的證據。** 這條規則在本書第 5 章、第 7 章各出現一次，這裡是它的第三個實例。

Gatekeeper 只在五筆以上才跑，因為三筆引用談不上「分布」。

### 存在查核：判準之前還有一關

```
⓪ 存在查核 — 七大判準之前

Finder 產出的紀錄存成檔案後跑腳本比對，不靠模型重讀：

    <驗證腳本> <紀錄檔>

腳本獨立讀取每筆的來源檔，對引文做三層比對
（逐字 → 標點／連字層級差異 → 最接近片段），
輸出六種狀態與對應處置，比對失敗時附上來源檔的實際文字。

由腳本讀而不是模型讀，正是要的「來源分離」——腳本沒有 Finder 的記憶可污染。
文字對不對是機械問題；能不能用是七大判準的事，
狀態表不能拿來取代判準審查。
```

**這一段在防什麼**：把「文字對得上」當成「這個引用可以用」。

最後那一句是整段的重點。存在查核只回答一個問題：那句話在不在。它不回答那句話能不能撐你的主張。

### 邊緣情況：這一節是撞出來的

節錄六列。原檔有二十多列。

```
| 情況 | 處理方式 |
|-----|---------|
| 全部 REJECT | 告知「目前沒有來源撐得住」，給出該找什麼證據 |
| 使用者堅持用被 REJECT 的 | 說明風險，提供最保守寫法，決定權在使用者 |
| 條目只有書目沒有全文 | 標「未經全文驗證」，不得撐因果／方法論主張 |
| 取全文失敗 | 維持「未經全文驗證」，不可寫成「沒有全文」。
              最常見是不在訂閱網段，與「該文沒有全文」意義完全不同 |
| 兩個檢索管道撞同一篇 | 不是兩個獨立佐證——它們的子來源本來就重疊 |
| 被引數要跨來源比較 | 不可直接互比，計算基礎不同 |
```

**這一段在防什麼**：每一列都是一次「當時想不到、事後才知道要防」。

⚠️ 第四列尤其值得看：**「取不到」跟「沒有」是兩件事，而工具回你的東西長得一模一樣。** 那一列不是設計出來的，是我把一篇拿得到的論文寫成「查無全文」之後補上的。

附錄 F 講的十二個設計模式，在這一份檔案裡可以逐個指出來：

| 附錄 F 的模式 | 在這份檔的哪裡 |
|---|---|
| ① 模式路由 | 「模式選擇（開場第一件事）」＋自動升級規則 |
| ② 角色分工與對抗 | Finder／Challenger／Gatekeeper 三個角色 |
| ③ 階段編號 | ⓪ 存在查核 → 七大判準 → 全域診斷 |
| ④ 人的關卡 | 「使用者堅持用被 REJECT 的」那一列，決定權明確交回 |
| ⑤ 逐項判準清單 | 七大判準表，「不可跳過」 |
| ⑥ 前置存在查核 | ⓪ 存在查核 |

## J-4　你的第一版不該長這樣

這是這一頁最重要的一節。

上面那份檔案有十八節。⚠️ **如果你看完決定坐下來寫一份十八節的技能檔，你會失敗，而且會失敗在你以為自己該懂但其實還沒遇到的地方。**

那些節不是設計出來的，是撞出來的。舉一個真的例子，這是它的變更紀錄裡的一則：

```
| 1.9.0 | 新增「確認知識庫有無筆記」的收尾步驟，無筆記者標「待建筆記」並交棒。
         觸發原因：本技能只回答「引用能不能用」，答完就停，
         導致引用進了草稿而來源沒留進知識庫。
         實測一份稿件，全稿引用 16 筆、知識庫僅 6 筆有筆記，
         其餘 10 筆都是判定可用之後就沒有下文——
         下次要用同一篇得重讀一次，
         而且當初判定可用的理由（哪一頁、什麼限制）只存在於那次對話。|
```

那一節不是我想到「應該要有收尾步驟」，是我數了一次 16 比 6。

**所以你的第一版該長什麼樣**：第 3 章 3.1 那個五段的版本。使用者背景、步驟、輸出格式、品質標準、不要做什麼。就這樣。

**然後照這個順序長**：

1. 被同一件事絆到第二次 → 在「不要做什麼」多寫一行
2. 發現自己每次都要先講一遍研究背景 → 把它寫進「使用者背景」
3. 開始覺得同一個技能有時要快有時要細 → 這時候才需要模式路由
4. 某次它給的東西你事後才發現不對 → 這時候才需要判準清單
5. 你開始不確定自己有沒有漏掉什麼 → 這時候才需要覆蓋範圍聲明

⚠️ **每一步的觸發條件都是一次真實的失誤，不是一個階段目標。** 沒被絆到就不要加——多加的每一條都是你以後要維護、而且不知道能不能刪的東西。

附錄 F 的模式增減判準是同一句話：**你上一次因為缺它而卡住是什麼時候？** 答不出來，就是還不需要。
